# The app page in 26 languages, and "Hent appen" on every localized page

Written 2026-11-03. The Danish `/download` (redesigned the same day) now has a version in each of the languages of the apps, with screenshots captured in
that language, and every localized page links to the version in its own language.

## URL scheme

| Page | URL |
|---|---|
| Danish (the source) | `/download` |
| the other 25 languages | `/<code>/download` — `en de fr nl it pl sv nb fi cs hu sl es pt sk el ro bg hr sr et lv lt mk sq` |

The codes are those of `i18n/languages.json` (the apps), so Norwegian is `nb` (the country pages for Norway are `/no/strompris`: a country prefix is
not a language prefix) and Serbian is `sr` (the page is in Latin script, `<html lang="sr-Latn">`, like the site's Serbian country pages).
`/da/download` is not a page. A page's own language tag maps to its code in `dlCode()` (Pris block): `nb`→`nb`, `sr-Latn` and `sr-ME`→`sr`, a language with
no page → `en`.

* **hreflang.** The 26 pages are translations of one page, so unlike the country pages (different markets, no cluster) they list each other: every page's
  head carries 26 `hreflang` links (its own included, `<html lang>` values such as `sr-Latn`) plus `x-default` = `/en/download`; the sitemap repeats the
  same 27 `xhtml:link` alternates per URL; each page's canonical is itself. The Danish `/download` gets the set too.
* **Sitemap, llms.txt, IndexNow.** The 25 new URLs are in `SITEMAP_URLS` (priority 0.6, lastmod `DOWNLOAD_LASTMOD`, bump it when the page changes).
  `llms.txt` has one line listing the 26 versions. `scripts/indexnow.mjs` submits whatever the live sitemap lists, so nothing to add there.
* **Structured data.** Each page has its own `MobileApplication` (`inLanguage`, text from the table, screenshots of its own language).
* **Header and footer of the app pages.** The logo, one button "Get the app" (this page, `aria-current`), no Danish menu, place chip, tab bar or net dialog;
  the footer lists the countries in the language (to their price pages), the 26 versions of the page by their own names, the pill, and the data line.

## One template, one text table, one status table

| File | What |
|---|---|
| `functions/_download.js` | the template (`downloadMain`), **`APPS`** (status of each product), **`FACTS`** (26 languages, 30 countries, minimum systems, the two store links), the list of languages |
| `functions/_download_i18n.js` | **`DL_TEXT`**: the words, one entry per language, the same keys everywhere |
| `functions/_download_img.js` | generated by `scripts/make-download-images.py localized`: which screenshot each slot shows |
| `scripts/sync-download-page.mjs` | writes the **Danish** `<main data-page="download">` of `index.html` from the template (`--check` is in the gate) |

The Danish page is rendered from the same template and its text is the `da` entry of the table; the rendered markup is byte for byte the page that was
deployed (only the comment about the status switch changed). `index.html` keeps it as plain HTML so the router shows it without a round trip and a
crawler reads it without script. The other languages are drawn by the Function into the same shell. The dev server (`server.js`) draws `/<lang>/download`
with the production Function, so what you see locally is what Pages serves.

**Change a status** (Mac approved, Watch released, reminders in the app): edit `APPS` in `functions/_download.js` — `data-status`, the chip text (in every
language, from the table) and the store link follow — then `node scripts/sync-download-page.mjs`, and add the product to the `features` of the table when it
is a live feature. Bump `DOWNLOAD_LASTMOD` and `/download` in `CONTENT_LASTMOD`. **Change a count** (languages, countries, minimum system): `FACTS`; strings
carry `{langs} {langs1} {countries} {countries1} {ios} {android} {mac} {n}`. The tests compare the counts with `i18n/languages.json` and the status
table with every page's cards.

The Watch work will change `cWatch` (and `APPS.watch`) only.

## The words (machine translations: native review needed)

`en` is the source of the translations and `da` the source of the wording. The other 24 were machine-translated from the English in November 2026,
language by language, with the app's own terms (`i18n/strings/<lang>.json`: Your price, Spot price, Smart home, cheap/expensive, forecast), the store
listings (`docs/store/<lang>.md`), the Android banner texts and the chrome words (`CHROME_I18N`) as the glossary. **No native speaker has read them.**
Review in this order: **de, fr, it, pl, es**, then nl, sv, nb, pt, cs, sk, hu, fi, then the rest. Things to look at first:

* `de`: "Endpreis" for Your price (the app's `mode_net_price`). `nb`: "Din pris" kept as in the app (Ditt pris?), "utheva" in `features`.
* `et`: informal "sina" like the app, the site chrome uses "te". `ro`: "tău" in the app and store, "vă" in the chrome.
* Widget: `pl` "Widżet", `sl` "Pripomoček", `lv` "Logrīks", `et` "Vidin", `bg` "Уиджет", `mk` "Виџет", `sq` and `fi` kept "widget"; Reminders: `sq` "Kujtesat".
* `cs` "Telefon s Androidem", `sl` "Tablica z Androidom" and the `getApp` labels are guesses.
* Plural forms of "26 languages" were checked by the translators for 26 and 25 only.

`getApp` is also the word of the header button and footer pill on the country pages (`CHROME_I18N.app`); a test keeps the two equal.

What the foreign pages say (and do not say). The main message is Europe: spot prices for 30 countries, hour by hour, the cheapest and the most expensive
hour; "Right now" (rating cheap/average/expensive); 2 or 5 days with a forecast "where the exchange has not priced the hours yet" (elpriser.org's own
statistical model, not an official one); Smart home. Denmark-only things (Your price with the grid company, tariffs, taxes, VAT, finding the grid company
by position, DK1 and DK2) sit in their own block marked as Denmark only, and outside Denmark the page says the prices are exchange prices without taxes,
grid fees and supplier margin. No open-model claim, no accuracy figure, no day count other than 2 and 5, no product other than the apps. Status: iPhone, iPad,
Android phone and tablet live; Mac live (macOS 1.3.0, 2026-11-08, same App Store page as the iPhone app); Watch live (iOS 1.3.0); reminders and widget "in the next version".

Ways to get the prices without the app: the other languages list the website (the country page in the language), Home Assistant and MCP. Shelly, the API
and /integrationer are Danish pages and are left to the Danish page.

## Screenshots

`python3 scripts/make-download-images.py localized --ios <dir> --android <dir>` converts the raw captures (not the framed store images) to WebP at 1x/2x:
phone 360/720, tablet 640/1280, q88 (q80 when a file would pass 110 KB), into `download/img/<lang>/<slot>-<w>.webp`. Six slots: `hero1`, `hero2`, `country`,
`smart`, `ipad`, `tablet`. Only the first is eager (`fetchpriority="high"`); a page loads about 25-45 KB of images first and at most 160 KB if both hero
phones are fetched at 2x. The whole set is 8.6 MB in the repository (284 files); no file is over 83 KB.

The sources are the raw captures of `ElpriserIOS/store/make_screenshots.py` and `ElpriserAndroid/store/make_assets.py` (branch
`worktree-agent-a7d46711a0a4c0506`, which is not merged; the raw captures are not tracked there either, they were read from that checkout's working
folder). They show each language's default country, not Denmark.

| Source | Languages |
|---|---|
| own iPhone and iPad captures, and Android phone and tablet | en de fr nl it pl sv nb fi cs hu es pt sk el ro hr (17) |
| own **Android** captures in the phone slots (the iOS set has no capture for these), the **English iPad** for the iPad slot, own Android tablet | sl bg sr et lv lt mk sq (8) |
| Danish page | its own Danish captures, unchanged |

Notes: the Serbian capture is the Android app in Cyrillic while the page is Latin; `mk` and `bg` are Cyrillic like their pages. When the iOS captures of the 8
missing languages are taken, rerun the script and the manifest changes by itself (the page never names a file, it reads the manifest). The Danish
captures show the Danish features (Din pris breakdown, five days, net companies); the other languages do not use them, because those features are
Denmark-only and the localized captures show the Europe app.

## "Hent appen" on every localized page

* **Country pages** (all 32 of `PRIS_COUNTRIES`): `chromeHTML` puts a button `app-btn` ("Last ned appen") after the place chip in the header, hidden on a
  phone like the Danish header's, and a pill `sf-getapp` in the footer (every width), both to `/<code>/download` for the page's language (`dlHref`). The
  Montenegrin page goes to `/sr/download`, the Belgian pages to `/nl/download` and `/fr/download`. The server draws it (`withCountryChrome`) and the
  browser does too (`localiseChrome`), from the same function of the Pris block.
* **The app pages**: header button (this page) and footer pill.
* **Danish pages** keep the header button and footer link to `/download`. The Danish chrome fixture is unchanged.
* The country pages' render cache key is `zone-ssr-v26` (v25 pages have no button).
* The Android Google Play banner stays on the country pages and is not shown on `/download` or `/<lang>/download` (it would repeat the page).
* **GA4 `store_click`**: the one delegated listener reads `lang` from `<html lang>`, so the app pages report `de`, `sr-Latn`, `nb` … and `placement`
  `hero` or `card`; no change to the listener.

## Tests

`node test-download-i18n.mjs` (in `npm run test:unit` and the gate): the table (every key, placeholders, lengths, no leftover Danish or English), the 26
languages against `i18n/languages.json`, every page (200, h1, lang, canonical, hreflang, og:locale, JSON-LD, sitemap alternates, llms.txt, cards/chips/links
from the one status table, truth rules, images exist/WebP/size/dimensions/eager, works without JS, header and footer), "Hent appen" on every country page,
and the dev server and router. `test-static.js` checks that the Danish `index.html` page equals the template output; `test-zone-pages.mjs` and
`test-forecast-chart.mjs` pin the country chrome (button and pill); `test-e2e.js` has browser tests (da, en, de, no, fr).

## Adding a language

A new app language: add it to `i18n/languages.json`, translate `DL_TEXT` (copy `en`), add the row to `DL_LANGS` (`_download.js`) and `DL_CODES` (Pris block),
add `app` to its `CHROME_I18N` entry, capture the screenshots and run the image script. The tests fail until every part is there.
